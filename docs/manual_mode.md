# Ручной режим работы

Пока нет постоянного хостинга, услугу можно оказывать вручную с компьютера.
Это не «костыль», а нормальный первый этап: вы проверяете, платят ли за это
деньги, и одновременно узнаёте, какие типы документов нужны клиентам.

## Что нужно

```bash
pip install -r requirements.txt
pip install -r requirements-ocr.txt   # OCR, если нужен фолбэк
```

Для OCR на Windows дополнительно установите Tesseract:
https://github.com/UB-Mannheim/tesseract/wiki — и добавьте в PATH.

## Как обработать чек

```bash
python scripts/parse_receipt.py чек.jpg
```

Команда попробует три пути по очереди:

1. **QR-код → ФНС** — читает QR, спрашивает ФНС, получает точные позиции.
   Это основной путь: точность не зависит от качества фото.
2. **QR-код есть, ФНС недоступен** — вернёт текст с предупреждением.
3. **QR-кода нет** — OCR по изображению (нужен Tesseract).

## Что выводится

Краткая сводка для проверки глазами, затем полный JSON:

```
Файл:      чек.jpg
Метод:     fns
Продавец:  ИП Иванов И.И. (ИНН 7701234567)
Дата:      2024-01-15T10:30:00
Итого:     1240.00 руб
Позиций:   2
   - Молоко 3.2% | 2 x 89.00 = 178.00 | НДС 10
   - Хлеб Бородинский | 3 x 59.00 = 177.00 | НДС 10
```

## Что отдать клиенту

```bash
python scripts/parse_receipt.py чек.jpg --out result.json --quiet
```

Файл `result.json` — то, что уходит клиенту. Внутри:

```json
{
  "method": "fns",
  "document_type": "receipt_kkt",
  "data": {
    "fiscal_number": "9280440300007971",
    "date_time": "2024-01-15T10:30:00",
    "total_sum": "1240.00",
    "seller": { "name": "...", "inn": "..." },
    "items": [
      { "name": "Молоко 3.2%", "quantity": "2", "price": "89.00", "sum": "178.00", "vat_rate": "10" }
    ]
  }
}
```

## Как это выглядит в деле

1. Клиент присылает фото чека и просит распознать.
2. Вы запускаете команду, отправляете `result.json`.
3. Берёте оплату.

На чек уходит 15–30 секунд. На первый взгляд медленно, но при 10 чеках
в день — это 5 минут работы, а чек от 89 ₽.

## Масштабирование

Ручной режим упирается примерно в 50–100 документов в день. Дальше нужен API.

Когда упрётесь — у вас уже есть:

- код API с авторизацией и биллингом (`app/`, деплой на Render)
- список реальных клиентов и понимание их форматов
- готовые тарифы

То есть переход на API — это включить хостинг, а не строить с нуля.

## Полезно фиксировать

Ведите таблицу: дата, тип документа, клиент, заняло минут, распозналось ли верно.
Через 20–30 документов будет видно:

- какие типы документов реально нужны (и стоит ли делать УПД)
- сколько времени занимает обработка
- где ошибки распознавания
