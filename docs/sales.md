# Продажи без регистрации: как вести первого клиента

Пока нет эквайринга, всё делается вручную. Схема одна, и она работает при любом
объёме.

## Путь клиента

```
лендинг → Telegram → бесплатный чек → перевод на карту → API-ключ
```

Ни одного шага, где нужно что-то регистрировать или подписывать.

---

## Шаг 1. Клиент написал в Telegram

Не спрашивайте сразу про деньги. Сначала бесплатный чек.

**Что написать:**

> Привет! Скиньте фото одного чека — разберу и верну JSON бесплатно, чтобы вы
> посмотрели, подходит ли вам. Если понравится — обсудим дальше.

**Что просить у клиента:**
- фото чека крупно, чтобы читался QR
- если чеков много — один самый сложный, с позициями

---

## Шаг 2. Разбираете чек

```bash
cd C:\Users\vladk\OneDrive\Desktop\Work\Work\user\docparser-ru
.venv\Scripts\python.exe scripts\parse_receipt.py "C:\путь\к\чеку.jpg" --out result.json
```

Смотрите сводку. Если `trustworthy: false` — **не отправляйте как есть**, скажите
честно: «вот эти цифры не подтвердились второй строкой, сверьте вручную». Лучше
один осторожный ответ, чем потом претензия.

Отправляете клиенту `result.json` и сводку текстом.

---

## Шаг 3. Клиенту понравилось

**Называете цену.** Ориентир для старта:

| Что предлагаете | Цена |
|----------------|------|
| Разовый чек | 2–3 BYN |
| 50 чеков в месяц | 10 BYN |
| 500 чеков в месяц | 20 BYN |
| 5 000 чеков в месяц | 49 BYN |

Первым клиентам — 2–3 BYN за чек. Это не про прибыль, это про проверку
гипотезы: **готовы ли вообще платить**. Если за разовый чек не платят, тариф не
предлагайте — там тем более не купят.

**Как просить оплату:**

> Работает, значит вопросов нет. Оплата переводом на карту: 2 BYN. После
> оплаты пришлю ключ API — сможете отправлять чеки сами, без меня.

Пришлите номер карты и имя получателя. Суммы лучше круглые, чек не нужен.

---

## Шаг 4. Деньги пришли → выдаёте доступ

```bash
python scripts\grant_access.py client@example.com --tier pro --name "ООО Ромашка"
```

Скрипт выдаст пароль и API-ключ. **Ключ показывается один раз** — сохраните.

Что отправляете клиенту:

```
Ваш доступ к DocParser.

Тариф: 500 чеков в месяц
API-ключ: dp_...
Пароль от личного кабинета: ...

Запрос:
POST https://<адрес>/api/v1/documents/parse
Заголовок: X-API-Key: dp_...
Файл: поле file, тип receipt_kkt
```

### Тарифы и лимиты

| Тариф | Чеков в месяц |
|-------|---------------|
| `free` | 50 |
| `starter` | 1 000 |
| `pro` | 10 000 |
| `business` | 50 000 |

### Кого и как проверить

```bash
python scripts\grant_access.py --list              # все клиенты
python scripts\grant_access.py email --revoke      # отозвать доступ
```

## Что делать, когда клиент вернулся с плохим фото

Самый частый случай и самый важный. Прогоняете стресс-тест на его файле:

```bash
python scripts\stress_test.py
```

Если чек не восстанавливается — говорите прямо: «на этом фото данные не
восстановить, нужно переснять». Это честно и это нормально. Выдумывать цифры
нельзя: одна ошибка в сумме стоит дороже десяти отказов.

---

## Учёт: держите таблицу

Файл `clients.csv` в корне, колонки:

```
date, client, channel, documents, amount, minutes, result
```

Через 20–30 чеков будет видно: какие форматы нужны, сколько времени уходит,
где ошибки. Это данные для следующего решения, а не ощущения.

---

## Когда регистрировать самозанятость

**Не раньше, чем доход станет стабильно выше 450 BYN в месяц.**

Причина: с 1 июля 2026 минимальный НПД — 45 BYN в месяц, даже при нулевом
доходе. Ниже 450 BYN налог 10% меньше минимума, и регистрация только добавит
расход. Официально: <https://nalog.gov.by/professional_income_tax/>

Порядок: [docs/payments.md](payments.md)

---

## Чего не делать

- **Не отправлять неподтверждённые цифры.** Флаг `trustworthy: false` — это не
  формальность, а предупреждение об ошибке в деньгах.
- **Не обещать скорость.** 5–10 секунд на чек — реальная цифра, не 1 секунда.
- **Не продавать API первым.** Первым идёт «я разберу ваш чек», API — вторым.
- **Не молчать о скидках и бонусах.** Если чек их содержит, парсер их покажет.
