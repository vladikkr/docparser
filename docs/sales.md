# Продажи: как вести первого клиента

Эквайринга нет: Stripe не работает с резидентами Беларуси. Поэтому оплата
ручная, а доступ выдаётся вручную. Схема одна, и она работает при любом
объёме.

## Путь клиента

```
лендинг → @docparser_by_bot → бесплатные документы → перевод → доступ открыт
```

Клиент не регистрируется и ничего не подписывает. Он просто пишет боту и
присылает фото. Дальше:

| Момент | Что происходит | Что делаете вы |
|---|---|---|
| Клиент прислал фото | Бот отвечает в том же чате | Ничего |
| Пробные документы кончились | Бот пишет «напишите @vladikskr» и присылает вам уведомление с кнопками | Ничего, пока не придёт оплата |
| Деньги пришли | Нажимаете «Выдать доступ» | Одно нажатие |
| Клиент хочет API, а не бота | `scripts\grant_access.py` | Одна команда |

Ваше действие на клиента — **одно нажатие кнопки**, и то только в момент оплаты.

## Шаг 1. Клиент пишет боту

Бот: **[@docparser_by_bot](https://t.me/docparser_by_bot)**

Ничего настраивать не надо. Клиент жмёт Start, присылает фото и получает
разбор в том же чате.

**Что попросить прислать:**
- чек — целиком, чтобы читался QR и был виден итог;
- если документов много — сначала один самый сложный, с позициями;
- XML-файлы (УПД, счёт-фактура, ТОРГ-12, акт) тоже можно — бот определит тип
  сам.

**Что бот делает с ответом:** сверяет сумму позиций с итогом и прямо пишет,
если не сошлось. Это главная ценность: клиент видит, что цифры не выдуманы.

## Шаг 2. Считаете, что готовы брать деньги

Повод для этого простой: клиент шлёт много документов, а три бесплатных
кончились. До этого момента разговор о деньгах не нужен.

**Что написать:**

> Бесплатные документы закончились, дальше можно за деньги — столько-то за
> столько. Если интересно, оплата переводом на карту, доступ включаю сразу.

## Шаг 3. Клиент платит

Способы — в `payments.md`. Коротко: перевод на карту.

## Шаг 4. Выдаёте доступ

В чате с ботом придёт уведомление с двумя кнопками. Нажмите **«Выдать
доступ»** — клиент сразу продолжит работать, ему придёт подтверждение.

Кнопки приходят только вам, потому что в `TELEGRAM_ADMIN_ID` вписан ваш
Telegram ID.

## Если клиенту нужен API, а не бот

Для интеграции с 1С или своей системой — `scripts\grant_access.py`:

```powershell
python scripts\grant_access.py <почта> --tier pro
```

## Запасной путь: бот не работает

Если бот недоступен (компьютер выключен, воркер не поднялся), разбор всё равно
можно сделать вручную — одна команда:

```powershell
python scripts\deliver.py чек.jpg
```

Скрипт печатает готовый ответ клиенту. Это медленнее и занимает ваше время,
поэтому бот и полезен, но знать про этот путь стоит.

## Чего не делать

- **Не просить фото в личку.** Клиент присылает боту сам, и вы ничего не
  пересылаете. Это и было целью.
- **Не обещать то, что не работает.** Если формат в разработке, бот так и
  пишет. Лучше, чтобы клиент узнал об этом сразу.
- **Не держать два процесса с одним токеном.** Локальная копия и воркер
  одновременно — Telegram отдаст 409 обоим, и ответы перестанут приходить.

## Проверки перед тем, как продавать

```powershell
python scripts\check_selfemployed.py   # чек самозанятого сквозным путём
python scripts\validate_all.py         # УПД, СФ, ТОРГ-12, акт, ЭТрН
python scripts\check_landing.py        # лендинг не врёт о статусах
```
