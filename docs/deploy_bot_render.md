# Развёртывание бота на Render (background worker)

Бот должен работать, когда твой компьютер выключен. Для этого он ставится на
Render как **background worker**, а не как web service.

## Почему worker, а не web service

Бот сам опрашивает Telegram по исходящему соединению, поэтому публичный адрес
ему не нужен вообще. На бесплатном тарифе web service Render усыпляет сервис
после простоя — отсюда и `404` на нашем прежнем `docparser-api-gn9d.onrender.com`.
Worker на бесплатном тарифе не засыпает и адреса не требует.

## Что уже готово в репозитории

- `docker/Dockerfile.bot` — образ с Tesseract и русским языковым пакетом.
  Сборка падает, если OCR в образе не работает: бот, который отвечает «не
  прочиталось» на каждое фото, хуже, чем бот, который не поднялся.
- `render.yaml` — воркер `docparser-bot` описан, но переменные помечены
  `sync: false` и должны быть вписаны вручную.
- `scripts/check_worker_startup.py` — проверки, которые важны именно на
  воркере: токен из окружения, создание каталога состояния, OCR, отсутствие
  запросов ввода, регистрация обработчиков, устойчивость к битым файлам.

Проверь локально перед деплоем:

```powershell
python scripts/check_worker_startup.py
```

## Шаги

### 1. Перевыпусти токен

Тот, что был в истории чата, в Render попадать не должен.

1. `@BotFather` → `/revoke` → выбери `docparser_by_bot`
2. Получи новый токен
3. Впиши его **себе** в `.env` через `python scripts\set_bot_token.py`

Новый токен в репозиторий не коммитится: `.env` в `.gitignore`.

### 2. Создай worker

В браузере на [dash.render.com](https://dash.render.com):

1. **New → Background Worker**
2. Подключи репозиторий `vladikkr/docparser`
3. Environment: **Docker**
4. Region: **Frankfurt** (ближе всего к Беларуси)
5. Instance type: **Free** (512 МБ — минимально рабочий, см. ниже)
6. Name: `docparser-bot`

Если создаёшь через Blueprint, Render прочитает `render.yaml` сам, и тогда
пунктов 3–5 можно не указывать.

### 3. Впиши переменные

В разделе **Environment** добавь:

| Ключ | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | новый токен от BotFather |
| `TELEGRAM_ADMIN_ID` | твой числовой ID: `1518791519` |
| `TELEGRAM_TRIAL_LIMIT` | `3` |
| `TELEGRAM_STATE_FILE` | `/app/storage/bot_users.json` |

`TELEGRAM_ADMIN_ID` уже вписан в твой локальный `.env`; значение выше — то
самое, что бот подтвердил командой `/id`.

Сохрани и дождись деплоя.

### 4. Проверь

В логах воркера должна появиться строка:

```
bot_started username=docparser_by_bot id=...
```

Потом напиши боту в Telegram:

1. `/start` — должен ответить приветствием и статусом пробных документов
2. Пришли `C:\Users\vladk\Downloads\1.png.jpg` — должен вернуть разбор чека
3. Пришли `test_xml\upd\upd_valid.xml` — должен вернуть 3 позиции и итог

## Про память

Бот в фоне занимает до **197 МБ** в процессе Python, и Tesseract добавляет свой
процесс в тот же лимит. Отсюда цифры в таблице хостингов:

- 128 МБ и 256 МБ — **не подходят**, OCR не запустится
- 512 МБ — минимально рабочий вариант, то, что выбран здесь
- 1 ГБ — комфортно, если воркер начнёт подтормаживать

Замерить можно так: `python scripts/check_memory.py`

## Если воркер не поднимается

| Симптом | Причина |
|---|---|
| `bot_started` нет, падает на импорте | Не сработал `RUN` из Dockerfile: проверь, что Tesseract в логе установки есть |
| `No module named telegram` | Собран не тот Dockerfile: должно быть `./docker/Dockerfile.bot` |
| `Conflict: terminated by other getUpdates` | Два процесса с одним токеном — локальный и воркер. Останови локальный: `scripts\bot_service.ps1 stop` |
| `TELEGRAM_BOT_TOKEN is not set` | Переменная не вписана или с опечаткой в имени |

**Важно:** не запускай локальную копию одновременно с воркером. Один токен
обслуживает только один процесс, и второй получит 409, а ответы перестанут
приходить обоим.
